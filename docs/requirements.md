# Kakeibo 要件定義書

## アプリの目的

個人の収支・残高を管理する家計簿アプリ。いつ・どの口座から・いくら入出金したかを記録・可視化する。将来的にグループ（同一生計者）の割り勘管理にも対応する。

---

## フェーズ構成

| フェーズ | 内容 |
| --- | --- |
| **フェーズ1（今回）** | 個人機能：ログイン・カレンダー・入出金管理・口座管理 |
| フェーズ2（後日） | グループ機能：メンバー管理・割り勘・共有家計簿 |

---

## フェーズ1 機能要件

### 1. 認証機能（Spring Security）

- ユーザー登録（ユーザー名・パスワード・表示名）
  - 誰でも自由に新規登録可能
  - パスワード要件：8文字以上 + 英数字混在必須
- ログイン / ログアウト
- ログイン中のユーザー名 / 表示名を画面に常時表示
- 自分のデータのみ表示・操作できる（他ユーザーのデータにアクセス不可）
- パスワードリセット機能はフェーズ2以降のスコープ

---

### 2. トップ画面（月間カレンダー）

**表示内容：**

- ログインユーザー名 / 表示名
- 現在の**総残高**（全口座の合算）
- **月間カレンダー**（7列 × 5行）
  - 各日付に：その日の収入・支出・収支を表示
  - 土曜・日曜は色分け
- 月の切り替えボタン（前月・翌月）

**操作：**

- 日付をクリック → その日の入出金入力画面へ

---

### 3. 入出金入力画面

**入力項目：**

| 項目 | 内容 |
| --- | --- |
| 日付 | 必須。カレンダーからの遷移時は自動セット |
| 収支タイプ | 必須。収入 / 支出 |
| カテゴリ | 必須。収支タイプに応じたカテゴリ一覧から選択（マスタ管理） |
| 金額 | 必須。1円以上の整数 |
| 口座 | 必須。登録済み口座から選択（マスタ） |
| 備考 | 任意。最大100文字 |

**機能：**

- 入力後に一覧画面（その日の取引）へ戻る
- バリデーションエラーはフォームのインラインに表示

---

### 4. 取引一覧・編集・削除

**表示：**

- 全件表示（ページネーションなし）
- デフォルトソート：日付の降順
- 一覧表示列：日付・カテゴリ・収支タイプ・金額・口座・備考

**フィルタ条件（複数組み合わせ可）：**

| 条件 | 内容 |
| --- | --- |
| カテゴリ | 選択したカテゴリで絞り込み |
| 収支タイプ | 収入のみ / 支出のみ |
| 口座 | 選択した口座で絞り込み |
| 備考 | キーワード部分一致で絞り込み |

**操作：**

- 各取引の編集・削除が可能

---

### 5. カテゴリマスタ管理

**デフォルトカテゴリ（変更・削除不可）：**

| 種別 | カテゴリ |
| --- | --- |
| 収入 | 給料・賞与・副収入・その他収入 |
| 支出 | 食費・日用品・交通費・娯楽費・医療費・光熱費・家賃・通信費・保険料・お年玉・母の日・父の日・その他支出 |

**ユーザー追加カテゴリ：**

- ユーザーが収入用・支出用を指定してカテゴリを追加・削除できる
- デフォルトカテゴリは編集・削除不可

---

### 6. 口座マスタ管理

- 口座の登録・編集・削除（画面）
- 登録項目：口座名・初期残高
- 口座別残高を自動計算（初期残高 ± 取引金額の合算）
- トップ画面の「総残高」は全口座残高の合算
- **口座の削除は論理削除（アーカイブ）**
  - 削除された口座は新規取引入力の選択肢に表示しない
  - 過去の取引データはそのまま保持・表示される

---

### 7. 月間サマリー

**表示内容：**

- 指定月の収入合計・支出合計・収支（差引）
- カテゴリ別内訳（収入）：カテゴリごとの金額一覧
- カテゴリ別内訳（支出）：カテゴリごとの金額一覧 + **支出の円グラフ**
- 口座別の残高一覧

## 対応デバイス・UI方針

- **対応デバイス**：PC + スマートフォン（レスポンシブデザイン対応）
- **対応ブラウザ**：Chrome・Edge・Safari の各最新版（IE・旧バージョン対応外）
- **エラー表示**：フォームのインライン表示（入力欄の直下にエラーメッセージ）

---

## 非機能要件

### パフォーマンス

- 想定データ規模：1ユーザーあたり数百〜数千件の取引
- 画面表示レスポンスタイム：2秒以内を目安とする

### セキュリティ

- パスワードはハッシュ化して保存（BCrypt）
- パスワード要件：8文字以上 + 英数字混在必須
- セッションタイムアウト：無操作から30分で自動ログアウト
- 他ユーザーのデータへのアクセスはサーバー側で拒否する
- HTTPS：ローカル開発環境では不要。本番デプロイ時に必須とする
- データバックアップ機能：フェーズ2以降のスコープ

## データモデル（フェーズ1）

```sql
User
  - id (PK)
  - username (unique)
  - password (hashed)
  - displayName

Account（口座マスタ）
  - id (PK)
  - user_id (FK → User)
  - name（例：現金、楽天銀行）
  - initialBalance（初期残高）
  - archived（論理削除フラグ）

Category（カテゴリマスタ）
  - id (PK)
  - user_id (FK → User, NULLはデフォルトカテゴリ)
  - name
  - type (INCOME / EXPENSE)
  - isDefault（デフォルトカテゴリフラグ）

Transaction（取引）
  - id (PK)
  - user_id (FK → User)
  - account_id (FK → Account)
  - category_id (FK → Category)
  - date
  - amount
  - type (INCOME / EXPENSE)
  - memo（最大100文字）
```

## 画面遷移

### 画面一覧

| 画面名 | URL（案） | 説明 |
| --- | --- | --- |
| ログイン画面 | `/login` | 未認証時のエントリーポイント |
| トップ（月間カレンダー） | `/` | ログイン後のデフォルト遷移先 |
| 取引一覧 | `/transactions` | 全取引をフィルタ付きで表示 |
| 取引入力 | `/transactions/new` | 新規入出金登録（連続入力モード） |
| 取引編集 | `/transactions/:id/edit` | 既存取引の編集（入力と別画面） |
| 月間サマリー | `/summary` | 月次集計・円グラフ表示 |
| 口座管理 | `/accounts` | 口座の登録・編集・論理削除 |
| カテゴリ管理 | `/categories` | ユーザー追加カテゴリの管理 |

### ナビゲーション構造

- **下部タブバー**（全画面共通・固定表示）
  - カレンダー / 取引一覧 / 入力（＋ボタン） / サマリー / 設定（口座・カテゴリ）
- PC では同タブバーを下部に表示（レスポンシブ対応）
- ヘッダーにユーザー表示名・ログアウトボタンを常時表示

### 遷移フロー

```text
[未ログイン]
  任意のURL → ログイン画面（/login）にリダイレクト
                ↓ 認証成功
              トップ（月間カレンダー）

[ログイン済み]
トップ（月間カレンダー）
  └─ 日付クリック → 取引入力画面（日付が自動セット）
                      ↓ 登録完了（画面に留まる・フォームリセット）
                    取引入力画面（連続入力可能）

取引一覧
  ├─ 編集ボタン → 取引編集画面 → 保存後：取引一覧に戻る
  └─ 削除ボタン → 確認ダイアログ → OK：即削除・一覧を更新

口座管理
  └─ 削除ボタン → 確認ダイアログ → OK：論理削除（アーカイブ）

カテゴリ管理
  └─ 削除ボタン → 確認ダイアログ → OK：即削除
```

### 画面遷移ルール

| ルール | 内容 |
| --- | --- |
| 未ログイン時のアクセス | ログイン画面にリダイレクト（Spring Security 標準） |
| ログイン成功後 | 常にトップ（月間カレンダー）へ遷移 |
| 取引入力後 | 画面に留まりフォームをリセット（連続入力モード） |
| 取引編集後 | 取引一覧画面に戻る |
| 削除実行時 | 全削除操作に確認ダイアログを表示 |

## 実装順序（フェーズ1）

1. プロジェクト構造を Gradle + PostgreSQL + React に再作成
2. `docker-compose.yml` で PostgreSQL 起動
3. Spring Security + `User` エンティティ + ログイン API
4. `Category` エンティティ・デフォルトカテゴリ初期データ・CRUD API
5. `Account`（口座）エンティティ・CRUD API（論理削除対応）
6. `Transaction` エンティティ（userId/accountId/categoryId付き）・CRUD API
7. カレンダー集計 API（月別・日別）
8. React フロントエンド：ログイン画面
9. React フロントエンド：トップ（月間カレンダー＋総残高）
10. React フロントエンド：入出金入力・一覧（フィルタ付き）・編集
11. React フロントエンド：口座管理・カテゴリ管理
12. React フロントエンド：月間サマリー（円グラフ含む）
13. 動作確認・テスト

## 検証方法

- `docker compose up -d` で PostgreSQL 起動
- `./gradlew bootRun` でバックエンド起動
- `cd frontend && npm run dev` でフロントエンド起動
- ブラウザで React アプリにアクセス
- ログイン → カレンダー表示 → 日付クリック → 入出金登録 → カレンダーに反映されることを確認
- 口座マスタ登録 → 残高がトップ画面に反映されることを確認
- 口座を論理削除 → 入力画面の選択肢から消えるが過去取引は残ることを確認
- スマートフォン表示でレイアウトが崩れないことを確認
